# Style guide — Metro Rush

Пять правил для изменений кода. Каждое — с местом в коде, где оно уже
выполнено, и проверкой, которая его ловит. Перед изменением кода прочитай
этот файл; после — `sh scripts/check.sh`.

## 1. Правила игры — чистые функции в game.js
Без `document`/`window`/`canvas`/`Math.random`, состояние не мутируется,
случайность приходит параметром.
- **Пример:** `step(world, dt, input, rng)` в `game.js` возвращает новый `world`,
  `rng` подаётся снаружи (`createRng(seed)`).
- **Проверка:** тест «step: не мутирует исходный мир», «spawnPattern: одинаковый seed — одинаковая трасса».

## 2. Внешний ввод валидируется первой строкой и громко
Отдельная `validateX()`, первой строкой операции; на плохом вводе — `TypeError`/
`RangeError` с понятным сообщением, а не тихий `null`/`false`.
- **Пример:** `validateCommand(command)` — первая строка `applyCommand()`.
- **Проверка:** тесты «validateCommand: …», «applyCommand: невалидная команда кидает исключение и не меняет мир».

## 3. Сбой внешней зависимости не роняет игру и объясняется игроку
Браузерные API (Web Audio, `localStorage`, fullscreen) могут отказать.
Оборачивай вызов, давай понятный запасной путь, не жди бесконечно.
- **Пример:** `loadBest()`/`saveBest()` в `main.js` — `try/catch`, при запрете
  хранилища рекорд живёт до перезагрузки, игра работает.
- **Проверка:** фича B в `docs/requirements.md` (тесты `test_audio.js`, браузерный сценарий без звука).

## 4. Тест сначала, через публичный интерфейс
Новое поведение — сначала падающий тест (skill `test-driven-development`),
потом минимальный код. Тесты вызывают экспортируемые функции, а не детали
реализации; только `node:test`/`node:assert`; одна проверка поведения на тест,
название на русском говорит, что сломалось.
- **Пример:** «shiftGear: на отсечке — late, без буста» — вызывает `shiftGear()`,
  проверяет результат.
- **Проверка:** `sh scripts/check.sh` (хук запускает его после каждой правки).

## 5. Не ослабляй проверку ради зелёного результата
Нельзя менять ожидания существующих тестов, удалять тесты или править
`scripts/check.sh`, чтобы стало зелёным, — только по явному поручению.
Не добавляй npm-пакеты, TypeScript и бандлеры ради маленькой правки.
- **Пример:** при демо хука тест `kmh(10)` временно ставили на 61 — хук показал
  FAIL, и тест вернули, а не «подогнали» функцию.
- **Проверка:** ревью diff — изменения в `test_game.js`/`scripts/check.sh` должны быть объяснены поручением.
