# Design

## Context

Мотивация — в proposal.md («Why»), требования — в `specs/garage` и `specs/car-upgrades`.

Что важно из текущего кода:
- Характеристики машины — глобальные константы и таблица, использованные прямо в
  функциях: `GEARS` в `rpm()`, `topSpeed()`, `engineAccel()` и `shiftGear()`
  (проверка «перекрута»), `NITRO_DURATION` в `applyCommand()`, `JUMP_HEIGHT` в `jumpHeight()`.
- `createWorld()` вызывается без аргументов в `main.js` (3 места), в
  `mcp/simulate.js` и в 14 тестах; `rpm`, `topSpeed`, `engineAccel` вызываются напрямую в тестах.
- `main.js` использует `NITRO_DURATION` для полоски нитро в HUD (`main.js:154`) и
  сам считает обороты по базовым `GEARS` для тахометра и звука двигателя
  (`displayRpm`, `main.js:119–121`) и для огней переключения (`main.js:162`).
- Клавиатура в `main.js` работает по `mode`: Enter запускает заезд в `menu`/`over`
  (`main.js:346–349`), Esc — пауза в `playing`/`paused`.
- Выход из заезда без аварии — пауза → «В меню» (`toMenu`, `main.js:289`): мир
  пересоздаётся, `gameOver()` не вызывается.
- Логика игры — чистые функции в `game.js` (style guide, правило 1); внешний ввод
  валидируется первой строкой и громко (правило 2); сбой браузерного API не роняет
  игру (правило 3). Образец хранения — `loadBest()`/`saveBest()` в `main.js`.
- Замер автопилотом (30 трасс × 30 с, тот же код): множитель **ускорения** ×1.3
  снижает очки на 15% (идеальных переключений 50% → 25%), ×1.1–1.2 почти не меняет
  дистанцию; множитель **диапазонов передач** ×1.05 / ×1.10 даёт +5% / +7% дистанции и
  +3% / +25% очков, ×1.15 — уже больше аварий (13/30 против 8/30).

## Goals / Non-Goals

**Goals:**
- Чёткое разделение: правила гаража и влияние улучшений — в `game.js` (тестируемо
  в Node), хранение, экраны и клавиши — в `main.js`/`index.html`/`styles.css`.
- Полная обратная совместимость: вызовы без уровней дают прежнее поведение
  байт-в-байт, поэтому MCP, skill баланса и 58 тестов не меняются.

**Non-Goals:**
- Изменения в `render.js` (косметика — отдельное изменение).
- Поддержка улучшений в MCP `simulate_run` и в автопилоте skill `metro-balance-check`
  (проверка уровней мотора делается скриптом skill'а на временной копии, см. tasks).
- Перенастройка баланса трассы под улучшения.

## Разделение ответственности

```
+---------------------------- game.js (чистая логика) ----------------------------+
| UPGRADES каталог: id, цены [50,120,250], эффекты по уровням                     |
| createGarage() -> { coins: 0, levels: {engine:0, nitro:0, jump:0} }             |
| parseGarage(raw)        -> гараж или пустой гараж (терпит мусор)                |
| creditCoins(garage, n)  -> новый гараж                                          |
| nextPrice(garage, id)   -> цена или null (макс.)                                |
| buyUpgrade(garage, id)  -> новый гараж | бросает TypeError/RangeError           |
| validateUpgradeLevels(levels), statsForLevels(levels) -> player.stats           |
|   stats = { gearScale, nitroDuration, jumpHeight }                              |
| createWorld(levels?)    -> player.stats = statsForLevels(levels)                |
| rpm / topSpeed / engineAccel / shiftGear учитывают gearScale (умолчание 1)      |
| jumpHeight и включение нитро берут значения из player.stats                     |
+-------------------------------------------+-------------------------------------+
                                            |
+---------------- main.js (браузер) --------v-------------------------------------+
| loadGarage()/saveGarage(): localStorage "metro-rush-garage" (JSON), try/catch   |
| finishRun(): creditCoins один раз за заезд — из gameOver() и из toMenu()        |
| mode "garage": экран гаража, клавиши заезда игнорируются, Esc — назад           |
| кнопки покупки -> buyUpgrade в try/catch, сообщение в role="status"             |
| start(): world = createWorld(garage.levels); HUD: чипы уровней,                 |
|   полоска нитро = nitroT / player.stats.nitroDuration,                          |
|   тахометр, огни и звук: rpm(speed, gear, player.stats.gearScale)               |
+-------------------------------------------+-------------------------------------+
                                            |
+---------- index.html / styles.css --------v-------------------------------------+
| <section id="garage">, кнопки «Гараж» в меню и на экране конца заезда,          |
| область сообщения (role="status"), чипы уровней в HUD                           |
+---------------------------------------------------------------------------------+
  render.js — без изменений
```

## Decisions

### 1. Мотор масштабирует диапазоны передач, а не ускорение
`stats.gearScale` = 1.00 / 1.03 / 1.06 / 1.10. Функции `rpm`, `topSpeed`,
`engineAccel` и `shiftGear` получают необязательный параметр `gearScale = 1` и
умножают на него `GEARS[i].min/max`; `updatePlayer` и `applyCommand` передают
`player.stats.gearScale`.
- *Почему:* замер показал, что масштаб передач реально улучшает результат на всех
  уровнях до ×1.10, а окно идеального переключения в долях оборотов сохраняется само.
- *Следствие:* все, кто считает обороты, должны учитывать `gearScale` — не только
  логика, но и приборы в `main.js` (тахометр, огни переключения, звук двигателя),
  иначе огни подскажут «идеально» раньше настоящего окна. `render.js` (эффект скорости
  камеры) оставлен на базовой шкале: он ограничен `Math.min` и ничего не ломает.
- *Альтернатива — множитель ускорения:* отвергнута замером: ×1.3 ухудшает очки на 15%,
  то есть платное «улучшение» делало бы игру хуже.
- *Альтернатива — масштаб до ×1.15:* отвергнута: заметно больше аварий.

### 2. Характеристики машины — в `player.stats`, а не в глобальных константах
`createWorld(levels)` кладёт в игрока `stats = { gearScale, nitroDuration, jumpHeight }`;
при отсутствии `stats` функции используют прежние константы.
- *Почему:* функции остаются чистыми, уровни не «протекают» между заездами, тесты
  и MCP без уровней работают как раньше.
- *Альтернатива — менять глобальные константы перед заездом:* отвергнута: скрытое
  изменяемое состояние, ломает детерминизм MCP и тестов.

### 3. Гараж — неизменяемое значение и чистые функции в `game.js`
Каждая операция возвращает новый объект гаража; ошибки — `TypeError` (не тот тип) и
`RangeError` (неизвестное улучшение, не хватает монет, макс. уровень) с текстом из спеки.
- *Почему:* правила покупки тестируются в Node, как фича A.
- *Альтернатива — логика в обработчиках кнопок `main.js`:* отвергнута — не тестируется
  `node:test`, нарушает правило 1 style guide.

### 4. Хранение — один JSON-ключ в `localStorage` рядом с рекордом
Ключ `metro-rush-garage`, значение `{ "coins": N, "levels": {...} }`; чтение через
`parseGarage`, запись в `try/catch` — как `saveBest`.
- *Альтернатива — отдельные ключи на монеты и уровни:* отвергнута — возможна
  рассинхронизация при сбое между записями.

### 5. Зачисление монет — одна функция `finishRun()` для обоих выходов из заезда
`gameOver()` (авария) и `toMenu()` (пауза → «В меню») вызывают `finishRun()`, которая
зачисляет `world.coins` и помечает заезд как зачтённый, чтобы не зачислить дважды.
- *Альтернатива — зачислять только в `gameOver()`:* отвергнута на ревью — монеты
  при выходе через паузу молча терялись.
- *Альтернатива — зачислять каждую монету сразу:* отвергнута — запись в хранилище каждый кадр.

### 6. Отдельный режим `garage` для клавиатуры
Открытие гаража сохраняет предыдущий экран и ставит `mode = "garage"`; в этом режиме
обработчик клавиш игнорирует Enter и клавиши заезда, Esc возвращает на предыдущий экран.
- *Почему:* сейчас Enter в режимах `menu`/`over` запускает заезд — без отдельного
  режима он стартовал бы под открытым гаражом.

### 7. UI проверяет заранее, логика проверяет всегда
Недоступные покупки рисуются выключенными, но `buyUpgrade` всё равно валидирует вход;
`main.js` ловит ошибку и показывает её текст в `role="status"`.

## Risks / Trade-offs

- [Изменение сигнатур `rpm`/`topSpeed`/`engineAccel`/`shiftGear` сломает тесты] →
  новые параметры необязательные с умолчанием 1; 58 тестов не меняются.
- [Мотор 3 повышает максимальную скорость до 224 км/ч — риск аварий] → предел ×1.10
  выбран по замеру (10/30 аварий против 8/30); каждый уровень проверяется скриптом
  skill'а `metro-balance-check` с критерием из спеки.
- [Прыжок 3 (×1.3) делает барьеры заметно проще] → эффект ограничен 3 уровнями и
  самой дорогой ценой; коэффициент — константа каталога.
- [Экономика: ~50–60 монет за 30-секундный заезд, улучшение до 3 уровня стоит 420
  монет] → около 7–8 заездов на одно улучшение; цены — константы каталога.
- [Игрок может отредактировать `localStorage`] → однопользовательская офлайн-игра;
  `parseGarage` лишь отсекает некорректные значения.

## Migration Plan

Миграции данных нет: новый ключ `metro-rush-garage`, при его отсутствии — пустой гараж.
Откат: удалить код гаража; ключ в `localStorage` просто перестанет читаться.

## Open Questions

- Точные цены и коэффициенты нитро и прыжка можно подстроить после игровых проб — это
  константы каталога; итоговые значения фиксируются в спеке через `/opsx:update`.
