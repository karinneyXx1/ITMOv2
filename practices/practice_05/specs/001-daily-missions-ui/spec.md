# Feature Specification: Ежедневные задания — интерфейс игрока

**Feature Branch**: `001-daily-missions-ui`

**Created**: 2026-10-19

**Status**: Draft (согласована с общим контрактом)

**Контракт**: [`specs/daily-missions-contract.md`](../daily-missions-contract.md) — общий контракт UI ↔ логика, принят владельцем продукта 2026-10-19. При расхождении спеки с контрактом прав контракт (принцип VI конституции). Изменения — только решением человека с обновлением обеих спек.

**Input**: User description: "Ежедневные задания. Каждый день игроку выдаются 3 задания (например: собрать монеты, сделать идеальные переключения передач, проехать дистанцию). Прогресс копится по всем заездам за день. За выполненное задание полагается награда монетами в кошелёк гаража, награду нужно забрать. На следующий день задания новые."

**Зона спеки**: только пользовательский интерфейс — где игрок видит задания, что он делает, какие состояния и сообщения видит, клавиатура и доступность. Генерация заданий, правила подсчёта прогресса, смена дня и хранение — в спеке логики (`specs/002-daily-missions-logic`). Данные, операции и ошибки, на которые опирается UI, зафиксированы в контракте; см. раздел «Что UI получает от логики».

## Clarifications

### Session 2026-10-19

- Q: Что делать с наградой за выполненное вчера задание, которую игрок не забрал до смены дня? → A: Она автоматически зачисляется в кошелёк гаража при первом входе в новый день, игрок видит сообщение «Вчерашние награды: +N монет в гараж».
- Q: Где игрок забирает награду — только на экране «Задания» или ещё и на экране «Заезд окончен»? → A: Только на экране «Задания». На экране итогов только подсказка и кнопка перехода в «Задания», Enter там по-прежнему запускает «Ещё заезд».
- Q: Показывать ли прогресс заданий во время заезда постоянно в HUD? → A: Нет. Только всплывающая надпись при выполнении задания, постоянной панели заданий в HUD нет.
- Q: На какие данные, операции и ошибки логики опирается UI (сессия согласования контракта, 2026-10-19)? → A: На общий контракт `specs/daily-missions-contract.md`. В спеке обновлены:
  - отметка «Новые!» — через `seen` / `markMissionsSeen`;
  - надпись в заезде — через `previewCompleted`;
  - блок экрана итогов — через `gains` / `completed` / `autoCredited` / `dayChanged`;
  - таймер — через `nextDayStart`;
  - ошибки «Забрать» — по `code` (раздел 4 контракта);
  - сбой сохранения — `saveMissions` → `false`;
  - тексты строк — по разделу 6 контракта, цели и награды в примерах — по разделу 2.5.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Посмотреть задания дня и прогресс (Priority: P1)

Игрок в главном меню видит, что есть ежедневные задания, открывает экран «Задания» и видит три задания: что сделать, сколько уже сделано из скольких, какая награда и в каком состоянии каждое задание. Там же видно, когда придут новые задания.

**Why this priority**: без этого экрана фича для игрока не существует. Остальные истории на нём держатся.

**Independent Test**: подставить состояние дня с тремя заданиями в разных состояниях (не начато, в процессе, выполнено, награда получена), открыть экран из меню и сверить тексты, прогресс, награды и состояния. Esc возвращает в меню.

**Acceptance Scenarios**:

1. **Given** открыто главное меню, **When** игрок смотрит на меню, **Then** рядом с кнопкой «Гараж» есть кнопка «Задания», на которой видно краткое состояние дня (например, «Задания 1/3»: сколько из трёх выполнено).
2. **Given** главное меню, **When** игрок нажимает «Задания» (мышью, касанием или Enter/Пробел на кнопке в фокусе), **Then** открывается экран «Задания» с тремя строками заданий в порядке монеты → идеальные переключения → дистанция, а клавиши заезда на нём не работают.
3. **Given** открыт экран «Задания», **When** игрок смотрит на строку задания, **Then** в ней есть формулировка по разделу 6 контракта («Собери 150 монет»), прогресс числом и полосой («60 / 150»), награда с иконкой монеты («+40») и состояние текстом, а не только цветом.
4. **Given** открыт экран «Задания», **When** игрок смотрит на подвал экрана, **Then** видна подсказка «Новые задания через Ч ч ММ мин» (по `nextDayStart`) и сколько монет сейчас в кошельке гаража.
5. **Given** открыт экран «Задания», **When** игрок нажимает Esc или кнопку «Назад», **Then** он возвращается на экран, откуда пришёл, и фокус стоит на кнопке «Задания».

### User Story 2 — Забрать награду за выполненное задание (Priority: P1)

Игрок выполнил задание, видит, что награда ждёт его, нажимает «Забрать» и сразу видит, что монеты пришли в кошелёк гаража.

**Why this priority**: награда — смысл заданий. Требование «награду нужно забрать» означает, что без явного действия игрока монеты не начисляются.

**Independent Test**: подставить одно выполненное задание с незабранной наградой (`progress === target`, `claimed: false`), открыть экран «Задания», нажать «Забрать». Проверить сообщение, новое значение кошелька на экране, состояние строки «Получено» и то же число монет в гараже.

**Acceptance Scenarios**:

1. **Given** задание выполнено и награда не забрана, **When** игрок открывает экран «Задания», **Then** в строке задания активна кнопка «Забрать +40», а строка выделена как готовая к получению.
2. **Given** кнопка «Забрать +40» в фокусе, **When** игрок нажимает Enter, Пробел или кликает по ней, **Then** счётчик кошелька на экране растёт на 40 (`reward`), строка переходит в состояние «Получено» (кнопки больше нет, вместо неё отметка), а в строке статуса появляется «+40 монет в гараж».
3. **Given** награда только что забрана, **When** игрок открывает гараж, **Then** в кошельке гаража та же сумма, что показана на экране «Задания».
4. **Given** выполнено несколько заданий, **When** игрок забирает награду за одно из них, **Then** фокус переходит на следующую кнопку «Забрать», а если таких нет — на кнопку «Назад».
5. **Given** логика отказала в выдаче награды (ошибка с `code` из раздела 4 контракта), **When** игрок нажал «Забрать», **Then** кошелёк не меняется, в строке статуса показан текст по FR-011/FR-022, а экран обновляется так, как предписано для этого `code`.
6. **Given** экран «Задания» открыт со вчерашнего дня, **When** игрок нажимает «Забрать» после полуночи (`stale-day`), **Then** в статусе показано «Задания устарели — наступил новый день», список меняется на задания нового дня, и, если `autoCredited > 0`, кошелёк растёт и показано «Вчерашние награды: +N монет в гараж».
7. **Given** есть хотя бы одна незабранная награда, **When** игрок в главном меню или на экране конца заезда, **Then** на кнопке «Задания» видна отметка «Награда!» (текст, не только цвет).

### User Story 3 — Видеть вклад заезда в задания (Priority: P2)

Во время заезда игрок узнаёт о выполнении задания в момент, когда это случилось. На экране конца заезда видит, как этот заезд продвинул каждое задание.

**Why this priority**: даёт связь «я поехал — задание продвинулось» и подталкивает сыграть ещё. Однако задания и награды работают и без этого, через экран «Задания».

**Independent Test**: подставить задание «Сделай 3 идеальных переключения» с прогрессом 2/3, сделать идеальное переключение в заезде, увидеть всплывающую надпись. Разбиться и увидеть на экране итогов прогресс «3 / 3» с прибавкой «+1» и пометкой «Выполнено!», а также подсказку забрать награду.

**Acceptance Scenarios**:

1. **Given** идёт заезд и задание ещё не выполнено, **When** `previewCompleted` по текущим итогам заезда впервые в этом заезде вернул id задания, **Then** по центру появляется короткая всплывающая надпись «Задание выполнено!» в стиле существующих надписей. Заезд не останавливается и не ставится на паузу.
2. **Given** заезд окончен (авария), **When** открывается экран «Заезд окончен», **Then** под статистикой есть блок «Задания дня» с тремя строками:
   - формулировка;
   - прогресс после заезда;
   - прибавка за заезд «+X» из `gains` (если X > 0);
   - пометка «Выполнено!» для id из `completed`.
3. **Given** на экране «Заезд окончен» есть незабранные награды, **When** игрок смотрит на блок «Задания дня», **Then** видна подсказка «Забери награду в «Заданиях»» и кнопка «Задания». Enter по-прежнему запускает «Ещё заезд».
4. **Given** игрок вышел из заезда через паузу → «В меню», **When** он открывает экран «Задания», **Then** прогресс за прерванный заезд уже учтён (так же, как монеты такого заезда идут в гараж).
5. **Given** заезд не продвинул ни одно задание (все `gains` = 0), **When** открыт экран «Заезд окончен», **Then** блок «Задания дня» показывает текущий прогресс без прибавок и не выглядит как ошибка.

### User Story 4 — Новый день и новые задания (Priority: P2)

На следующий день игрок открывает игру и видит новые задания. Он понимает, что старые сменились, и знает, когда придут следующие.

**Why this priority**: обновление — суть «ежедневных» заданий. Для UI это переход состояния и одно сообщение, а не новый экран.

**Independent Test**: подставить вчерашнее состояние дня, перевести «текущее время» на следующий день, загрузить страницу, открыть меню и экран «Задания». Должны быть три новых задания с нулевым прогрессом и сообщение о новом дне.

**Acceptance Scenarios**:

1. **Given** со вчерашней игры наступил новый день, **When** игрок загружает игру и видит меню, **Then** кнопка «Задания» показывает «Задания 0/3» и отметку «Новые!» (`seen: false`) до первого открытия экрана «Задания» в этот день.
2. **Given** наступил новый день, **When** игрок впервые за день открывает экран «Задания», **Then** видны три новых задания с прогрессом 0 и строка статуса «Новые задания на сегодня». После этого состояние помечается просмотренным (`markMissionsSeen`), и отметка «Новые!» больше не показывается.
3. **Given** экран «Задания» открыт в момент смены дня, **When** очередная проверка дня (`ensureMissionDay`, не реже раза в минуту) вернула `dayChanged: true`, **Then** список обновляется на новые задания без перезагрузки страницы, а строка статуса сообщает «Наступил новый день — задания обновлены».
4. **Given** вчера остались незабранные награды, **When** логика актуализировала день и вернула `autoCredited > 0`, **Then** награды уже в кошельке гаража, и игрок один раз видит сообщение «Вчерашние награды: +N монет в гараж» (FR-016).

---

### User Story 5 — Все задания дня закрыты (Priority: P3)

Игрок выполнил и забрал все три задания и видит, что на сегодня всё сделано и когда ждать новые.

**Why this priority**: конечное состояние дня. Без него экран выглядит «пустым», но базовая ценность фичи от него не зависит.

**Independent Test**: подставить три задания с `claimed: true`, открыть экран. Должна быть плашка «Все задания на сегодня выполнены!» и таймер до новых.

**Acceptance Scenarios**:

1. **Given** все три задания получены, **When** игрок открывает экран «Задания», **Then** сверху видна плашка-стикер «Все задания на сегодня выполнены!» и строка «Новые задания через Ч ч ММ мин», строки заданий остаются видны в состоянии «Получено».
2. **Given** все три задания получены, **When** игрок в меню, **Then** кнопка «Задания» показывает «Задания 3/3» без отметок «Награда!» и «Новые!».

---

### Edge Cases

- **Задания недоступны**: при загрузке или показе логика бросила исключение, не относящееся к «Забрать». Экран «Задания» открывается и показывает «Задания сейчас недоступны. Заезды и гараж работают как обычно.», кнопка «Назад» работает. Меню, заезд, гараж и экран итогов работают как без фичи, блок «Задания дня» на экране итогов скрыт (принцип III конституции, контракт раздел 4). Повреждённое сохранение сюда не относится: `parseMissions` превращает его в корректное состояние, и игрок видит обычные задания дня.
- **Сохранение не удалось** (`saveMissions` вернул `false`): забранная в этой сессии награда видна в кошельке до перезагрузки. Игроку один раз за сессию показывается ненавязчивое «Прогресс заданий не сохранится после перезагрузки», игра не падает.
- **Двойное нажатие «Забрать»** (два быстрых клика, удержание Enter): награда начисляется один раз, после первого нажатия кнопка исчезает или становится неактивной. Если второе нажатие всё же дошло до логики, приходит `already-claimed`, кошелёк не меняется.
- **Несколько заданий выполнены в одном заезде одновременно** (`previewCompleted` вернул сразу несколько новых id): показывается одна надпись «Задания выполнены: N».
- **Надпись о задании совпала с другой надписью** («Идеально! +300»): обе должны быть прочитаны. Надпись о задании показывается сразу после текущей, а не затирает её.
- **Задание выполнено, награда не забрана, игрок сразу начинает новый заезд**: прогресс выполненного задания не растёт (`gains` = 0, показывается «цель / цель»), награда продолжает ждать, повторной надписи «Задание выполнено!» нет.
- **Заезд дал больше, чем нужно до цели** (собрано 57 монет, а до цели оставалось 30): прогресс показывается «150 / 150», прибавка «+30» (реально прибавленное из `gains`), полоса заполнена.
- **Смена дня во время заезда**: UI не прерывает заезд и не показывает смену дня в HUD. Итоги заезда засчитываются дню на момент окончания заезда (контракт, раздел 5). Если `dayChanged: true`, блок «Задания дня» на экране итогов показывает задания нового дня с прибавками этого заезда и строку «Наступил новый день — задания обновлены». При `autoCredited > 0` показано также «Вчерашние награды: +N монет в гараж».
- **Смена дня между открытием экрана и нажатием «Забрать»** (`stale-day`): см. US2-6 и FR-011. Награда за то задание не теряется — она приходит через автозачисление (`autoCredited`).
- **Игрок не заходил несколько дней**: зачисляются только незабранные награды последнего сохранённого дня, пропущенные дни ничего не дают (контракт, раздел 3). Сообщение показывается одно.
- **Длинные формулировки и большие числа** (самая длинная — «Сделай 12 идеальных переключений», самое большое число — «6 000 м», узкий экран телефона): текст переносится, а не обрезается. Числа с разделителем тысяч, строка читаема при ширине 360 px.
- **Экран «Задания» на тач-устройстве**: все действия доступны касанием, кнопки не меньше 44×44 px.

## Requirements *(mandatory)*

### Functional Requirements

**Точки входа и экраны**

- **FR-001**: В главном меню MUST быть кнопка «Задания» во вторичном стиле (как «Гараж»). На ней показывается краткое состояние «Задания N/3», где N — число заданий дня с `completed: true` (с полученной наградой или без).
- **FR-002**: На кнопке «Задания» MUST показываться текстовая отметка:
  - «Награда!» — если есть хотя бы одно задание с `completed && !claimed`;
  - иначе «Новые!» — если в состоянии дня `seen: false`.

  «Награда!» важнее «Новые!». При открытии экрана «Задания» UI вызывает `markMissionsSeen` и сохраняет состояние (контракт, раздел 5), после чего отметка «Новые!» в этот день не показывается.
- **FR-003**: Экран «Задания» MUST открываться из главного меню и с экрана «Заезд окончен» (как гараж). Во время заезда и на паузе он не открывается.
- **FR-004**: Экран «Задания» MUST быть оформлен как существующие карточки (белая карточка, обводка, жёсткая тень, кнопки-пилюли, шрифты по docs/DESIGN.md). Весь текст на русском.
- **FR-005**: На экране «Задания» MUST быть показаны:
  - заголовок «Задания дня»;
  - три строки заданий в порядке из состояния дня (монеты, идеальные переключения, дистанция);
  - текущий кошелёк гаража с иконкой монеты;
  - строка статуса для сообщений;
  - время до новых заданий;
  - кнопка «Назад» с подсказкой клавиши Esc.

**Строка задания**

- **FR-006**: Каждая строка задания MUST показывать:
  - формулировку по разделу 6 контракта: `coins` → «Собери <цель> монет», `perfectShifts` → «Сделай <цель> идеальных переключений», `distance` → «Проедь <цель> м» с разделителем тысяч (например «Проедь 3 000 м»);
  - прогресс «`progress` / `target`» в единицах вида (монеты, переключения, м);
  - полосу прогресса;
  - награду «+`reward`» с иконкой монеты;
  - состояние словом.

  Формулировку строит UI по полю `type`. От логики экранный текст не ожидается.
- **FR-007**: Строка задания MUST находиться ровно в одном из состояний, вычисляемых из данных по разделу 6 контракта. Каждое однозначно различимо текстом (не только цветом):
  - **«Не начато»** — `progress === 0`, полоса пустая;
  - **«В процессе»** — `0 < progress < target`;
  - **«Выполнено — забери награду»** — `completed && !claimed`, видна активная кнопка «Забрать +N»;
  - **«Получено»** — `claimed`, есть отметка «Получено», кнопки нет, строка приглушена.
- **FR-008**: UI MUST показывать прогресс таким, каким его вернула логика (по контракту `0 ≤ progress ≤ target`). Если всё же пришло значение вне диапазона, UI зажимает его в 0…цель для отображения и не падает.

**Получение награды**

- **FR-009**: Награду MUST выдавать только явное действие игрока (кнопка «Забрать +N»). Автоматически при выполнении задания монеты в кошелёк не начисляются. Кнопка «Забрать» есть только на экране «Задания». На экране «Заезд окончен» и в других местах кнопок получения награды нет.
- **FR-010**: После успешного `claimMissionReward` UI MUST сразу, без перехода между экранами:
  - сохранить гараж и задания;
  - обновить кошелёк на экране;
  - перевести строку в «Получено»;
  - показать в строке статуса «+`reward` монет в гараж».

  Новое значение кошелька MUST совпадать с тем, что увидит игрок в гараже.
- **FR-011**: Если `claimMissionReward` бросил ошибку, UI MUST оставить кошелёк без изменений и показать сообщение в строке статуса с пометкой «ошибка» по стилю, как в гараже. Дальнейшие действия зависят от `code` (контракт, раздел 4):
  - `stale-day`: показать «Задания устарели — наступил новый день», вызвать `ensureMissionDay`, сохранить, перерисовать экран заданиями нового дня. При `autoCredited > 0` обновить кошелёк и дописать «Вчерашние награды: +N монет в гараж»;
  - `unknown-mission`: показать текст ошибки, перерисовать список (см. спорное место в Notes чеклиста);
  - `not-completed`: показать текст ошибки («Задание ещё не выполнено: <прогресс> из <цель>»);
  - `already-claimed`: показать «Награда за задание уже получена», перерисовать строку;
  - `invalid-input` и любая ошибка без известного `code`: показать общий текст по FR-022.
- **FR-012**: Повторное нажатие «Забрать» до обновления экрана MUST NOT приводить ко второму начислению: кнопка становится неактивной сразу после нажатия.

**Заезд и итоги**

- **FR-013**: Во время заезда UI MUST показывать всплывающую надпись «Задание выполнено!», когда `previewCompleted(state, текущие итоги заезда)` возвращает id, ещё не объявленный в этом заезде. Если таких id несколько одновременно, показывается одна надпись «Задания выполнены: N». Надпись о задании не затирает другую всплывающую надпись, а идёт следом. Состояние заданий во время заезда не сохраняется. Постоянной панели заданий в HUD нет.
- **FR-014**: На экране «Заезд окончен» MUST быть блок «Задания дня», построенный по результату `applyRunToMissions`:
  - для каждого задания — формулировка, прогресс после заезда, прибавка «+X» из `gains[id]` (если X > 0) и пометка «Выполнено!» для id из `completed`;
  - при `dayChanged: true` — строка «Наступил новый день — задания обновлены»;
  - при `autoCredited > 0` — сообщение FR-016;
  - если есть задания с `completed && !claimed` — подсказка «Забери награду в «Заданиях»» и кнопка «Задания».

  Кнопка «Ещё заезд» и клавиша Enter работают как прежде.
- **FR-015**: Итоги заезда MUST применяться к заданиям ровно один раз за заезд. Это происходит и при аварии, и при выходе через паузу → «В меню», в тот же момент, когда монеты заезда зачисляются в гараж (контракт, раздел 5).

**Новый день**

- **FR-016**: Незабранные награды за выполненные задания прошедшего дня MUST автоматически зачисляться в кошелёк гаража при первой актуализации дня (`ensureMissionDay` или `applyRunToMissions` вернули `autoCredited > 0`). Это единственное исключение из FR-009. UI MUST один раз показать «Вчерашние награды: +N монет в гараж» (N = `autoCredited`) там, где произошла актуализация:
  - при загрузке страницы — в главном меню, в строке статуса под кнопкой «Задания»;
  - при открытии экрана «Задания», ежеминутной проверке на нём или ответе `stale-day` — в строке статуса экрана, кошелёк на экране обновляется;
  - в конце заезда — на экране «Заезд окончен».

  При `autoCredited = 0` сообщение не показывается.
- **FR-017**: При первом за день открытии экрана «Задания» (`seen: false`) UI MUST показать в строке статуса «Новые задания на сегодня». Пока экран открыт, UI MUST вызывать `ensureMissionDay` не реже раза в минуту. При `dayChanged: true` список обновляется без перезагрузки страницы с сообщением «Наступил новый день — задания обновлены».
- **FR-018**: Экран «Задания» MUST показывать время до новых заданий, вычисленное как `nextDayStart(сейчас) − сейчас`, в виде:
  - «Новые задания через Ч ч ММ мин»;
  - меньше часа — «через ММ мин»;
  - меньше минуты — «меньше минуты».

  Значение обновляется не реже раза в минуту, пока экран открыт.
- **FR-019**: Когда все три задания `claimed`, экран «Задания» MUST показывать плашку «Все задания на сегодня выполнены!».

**Ошибки и устойчивость**

- **FR-020**: Если при загрузке или показе заданий логика бросила любое исключение (кроме ошибок «Забрать», которые обрабатывает FR-011), UI MUST перейти в состояние «Задания сейчас недоступны»:
  - экран «Задания» показывает «Задания сейчас недоступны. Заезды и гараж работают как обычно.»;
  - кнопка «Задания» в меню показывает «Задания —» без отметок;
  - блок на экране итогов скрыт;
  - остальная игра работает без изменений.
- **FR-021**: Если `saveMissions` вернул `false`, UI MUST не прерывать игру и один раз за сессию показать «Прогресс заданий не сохранится после перезагрузки».
- **FR-022**: Игрок видит только русские понятные тексты. Для ошибок с `code` `stale-day`, `not-completed` и `already-claimed` показывается `message` из логики. Для `invalid-input` и ошибок без известного `code` показывается общий текст «Не удалось забрать награду. Попробуй ещё раз.», а технические подробности уходят только в консоль.

**Клавиатура и доступность**

- **FR-023**: Экран «Задания» MUST иметь собственный режим экрана (как гараж; в контракте — режим `missions`):
  - клавиши заезда (стрелки, Пробел-прыжок, E/Q/Shift/Ctrl, N, ↓) и Enter-старт заезда на нём не срабатывают;
  - Esc закрывает экран и возвращает туда, откуда он открыт;
  - M (звук) и F (полный экран) работают как везде;
  - клавиши читаются по физическому коду клавиши (работают при русской раскладке).
- **FR-024**: При открытии экрана «Задания» фокус MUST ставиться на саму карточку экрана, а не на кнопку, чтобы Enter, нажатый для открытия, случайно не «забрал» награду.
  - Tab / Shift+Tab переходят по кнопкам «Забрать» и «Назад» по порядку.
  - Enter и Пробел нажимают кнопку в фокусе.
  - У всех кнопок виден контур фокуса.
- **FR-025**: После закрытия экрана «Задания» фокус MUST возвращаться на кнопку «Задания» того экрана, откуда игрок пришёл.
- **FR-026**: Для экранных чтецов:
  - у экрана MUST быть доступное имя «Задания дня»;
  - каждая полоса прогресса сообщает текущее значение, цель и единицы;
  - у кнопки «Забрать» полное имя («Забрать награду 40 монет за задание: Собери 150 монет»);
  - строка статуса озвучивается при изменении (вежливое объявление);
  - всплывающая надпись в заезде использует существующий вежливый канал объявлений.
- **FR-027**: При включённом в системе «уменьшении движения» анимации заполнения полос, появления плашек и всплывающих надписей MUST отключаться или заменяться мгновенной сменой состояния.

### Что UI получает от логики (по контракту)

Источник истины — [`specs/daily-missions-contract.md`](../daily-missions-contract.md), разделы 2–6. Ниже — какие его части использует UI и для каких требований.

**Данные** (контракт, раздел 2):
- **Состояние дня**: `{ day, missions, seen }`:
  - `day` — местная дата `YYYY-MM-DD`;
  - `missions` — ровно три задания в порядке `coins`, `perfectShifts`, `distance`;
  - `seen` — для отметки «Новые!» (FR-002, FR-017).
- **Строка для показа**: `describeMissions(state)` → `[{ id, type, level, target, progress, completed, claimed, reward }]`:
  - `id` = `"<day>:<type>"`;
  - `0 ≤ progress ≤ target`;
  - `completed` = `progress === target`.

  Используется в FR-001, FR-002 и FR-005–FR-008.
- **Цели и награды**: лёгкое / среднее / сложное — награда 20 / 40 / 60:
  - `coins` — 60 / 150 / 300;
  - `perfectShifts` — 3 / 8 / 12;
  - `distance` — 1 000 / 3 000 / 6 000 м.

  UI их не вычисляет, только показывает.

**Операции** (контракт, раздел 3) и когда UI их вызывает (раздел 5):

| Операция | Когда вызывает UI | Что UI берёт из результата | Требования |
|---|---|---|---|
| `dayKey(ts)` | перед учётом заезда и «Забрать» | ключ дня | FR-011, FR-014 |
| `nextDayStart(ts)` | при показе экрана «Задания» и раз в минуту | момент смены дня для таймера | FR-018 |
| `parseMissions(raw, day)` | загрузка страницы (`loadMissions`) | корректное состояние (не бросает) | Edge Cases |
| `ensureMissionDay(state, garage, day)` | загрузка страницы; открытие экрана «Задания»; раз в минуту на нём; после `stale-day` | `state`, `garage`, `autoCredited`, `dayChanged` | FR-016, FR-017, FR-011 |
| `markMissionsSeen(state)` | открытие экрана «Задания» | состояние с `seen: true` | FR-002, FR-017 |
| `runResultsFromWorld(world)` | каждый кадр заезда и в конце заезда | итоги `{ coins, perfectShifts, distance }` | FR-013, FR-014 |
| `previewCompleted(state, results)` | каждый кадр заезда | `[id]`, впервые доведённые до цели (без изменения состояния) | FR-013 |
| `applyRunToMissions(state, garage, results, day)` | конец заезда, ровно один раз (`finishRun`) | `state`, `garage`, `autoCredited`, `dayChanged`, `gains`, `completed` | FR-014, FR-015, FR-016 |
| `claimMissionReward(state, garage, id, day)` | кнопка «Забрать» | `state`, `garage`, `reward` | FR-009–FR-012 |
| `describeMissions(state)` | любой показ заданий | строки для показа | FR-001–FR-008 |

**Хранение** (контракт, раздел 5):
- ключ `metro-rush-missions`;
- `saveMissions(state)` → `true` / `false`, где `false` означает FR-021;
- после любого изменения кошелька сохраняются и гараж, и задания.

**Ошибки** (контракт, раздел 4):
- `TypeError` или `RangeError` с полем `code`; при ошибке состояние и гараж не меняются;
- `code`: `invalid-input`, `stale-day`, `unknown-mission`, `not-completed`, `already-claimed`;
- реакция UI на каждый `code` — FR-011 и FR-022;
- любое другое исключение при загрузке или показе — FR-020.

**Тексты**: формулировки заданий и единицы строит UI по `type` (контракт, раздел 6). От логики экранные тексты приходят только в `message` ошибок.

**Тестовый хук**: состояние заданий доступно автотестам как `window.__metro.missions` (контракт, раздел 5).

### Key Entities

- **Задание дня**: то, что игрок видит строкой. Вид (`type`), формулировка, цель, прогресс, награда, состояние («Не начато» / «В процессе» / «Выполнено — забери награду» / «Получено»).
- **Состояние дня**: три задания одного местного дня и признак «экран просмотрен сегодня». Момент появления следующего набора UI получает отдельно (`nextDayStart`).
- **Итог заезда для заданий**: прибавка каждого задания за заезд (`gains`), задания, выполненные этим заездом (`completed`), признак смены дня и сумма автозачисления.
- **Кошелёк гаража**: существующий общий кошелёк монет. Награды пополняют его, задания своих монет не хранят.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Игрок из главного меню видит задания дня и их прогресс не более чем за 1 действие (одно нажатие кнопки «Задания»).
- **SC-002**: Игрок забирает готовую награду из главного меню не более чем за 2 действия (открыть «Задания» → «Забрать»), используя только клавиатуру или только мышь/касание.
- **SC-003**: В 100% случаев после «Забрать» сумма кошелька на экране «Задания» совпадает с суммой в гараже, а повторные нажатия не дают второго начисления.
- **SC-004**: По любой строке задания игрок без подсказок определяет её состояние из четырёх. Проверяется тем, что у каждого состояния есть уникальная текстовая метка, видимая без опоры на цвет.
- **SC-005**: При недоступных заданиях (сбой загрузки или сохранения) игрок может начать заезд, закончить его и купить улучшение в гараже так же, как без фичи: ни одного зависания или пустого экрана.
- **SC-006**: Все действия экрана «Задания» выполнимы только клавиатурой, ни одна клавиша заезда не срабатывает, пока экран открыт.
- **SC-007**: Экран «Задания» и блок «Задания дня» на экране итогов читаются без горизонтальной прокрутки при ширине экрана 360 px.
- **SC-008**: В 100% случаев незабранная награда прошедшего дня оказывается в кошельке гаража при первой актуализации нового дня. Сообщение «Вчерашние награды: +N монет в гараж» показывается ровно один раз, а N совпадает с приростом кошелька.

## Assumptions

- Заданий в день ровно 3, по одному каждого вида, в порядке монеты → идеальные переключения → дистанция (контракт, раздел 2.1). Вёрстка рассчитана на 3 строки. Новые виды в будущем UI покажет по той же схеме строки после добавления формулировки в раздел 6 контракта.
- «День» — календарная дата по местному времени игрока, момент смены — `nextDayStart` (контракт). UI только показывает время до смены и реагирует на неё.
- Награда вручную забирается только на экране «Задания» (Clarifications, 2026-10-19). Так одно место выдачи монет, как одно место покупки в гараже. Автозачисление вчерашних наград (FR-016) — системное действие, а не второе место выдачи.
- Во время заезда прогресс заданий не показывается постоянно (по DESIGN.md «без постоянного шума» в HUD), только всплывающая надпись при выполнении (Clarifications, 2026-10-19).
- Экран «Задания» не открывается из гаража и не показывается в гараже. Гараж лишь отражает пополненный кошелёк.
- Горячей клавиши для открытия «Заданий» из меню нет, как и для гаража. Доступ — кнопкой и через Tab.
- Числа в примерах взяты из таблицы целей контракта (раздел 2.5). Реальные цели и награды на конкретный день задаёт логика.
- Подсказка «Прогресс не сохранится» показывается не чаще раза за сессию, чтобы не мешать.
- Существующее поведение меню, паузы, экрана итогов и гаража сохраняется. Добавляются только новая кнопка, новый блок и новый экран (принцип V).
