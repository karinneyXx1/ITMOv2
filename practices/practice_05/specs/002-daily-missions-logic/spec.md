# Feature Specification: Ежедневные задания — логика

**Feature Branch**: `002-daily-missions-logic`

**Created**: 2026-10-19

**Status**: Draft

**Input**: User description: "Ежедневные задания. Каждый день игроку выдаются 3 задания (например: собрать монеты, сделать идеальные переключения передач, проехать дистанцию). Прогресс копится по всем заездам за день. За выполненное задание полагается награда монетами в кошелёк гаража, награду нужно забрать. На следующий день задания новые."

**Зона спеки**: только правила и данные (что такое задание, как выбирается набор дня, как считается
прогресс, когда задание выполнено, как начисляется награда, смена дня, ошибки, хранение, интерфейс
логики для остальной игры). Экраны, кнопки, тексты и их состояния описывает отдельная UI-спека;
обе спеки сводятся в общий контракт до плана (конституция, принцип VI).

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Набор заданий дня (Priority: P1)

Игрок открывает игру и получает три задания на сегодня. Каждое задание — это цель («собрать N монет»,
«сделать N идеальных переключений», «проехать N метров»), текущий прогресс (в начале дня 0) и размер
награды. В течение дня набор не меняется, сколько бы раз игрок ни перезапускал игру.

**Why this priority**: без набора дня нет ни прогресса, ни наград — это основа фичи.

**Independent Test**: запросить набор на заданную дату дважды (в том числе после «перезапуска» —
сохранения и чтения состояния) и убедиться, что это одни и те же 3 задания с прогрессом 0.

**Acceptance Scenarios**:

1. **Given** у игрока нет сохранённых заданий, **When** игра запрашивает задания на 19.10.2026,
   **Then** логика выдаёт ровно 3 задания разных видов, у каждого цель > 0, прогресс 0, награда > 0,
   не выполнено, награда не забрана.
2. **Given** набор на 19.10.2026 уже выдан и сохранён, **When** игра перезапущена в тот же день,
   **Then** выдаётся тот же набор (те же виды, цели, награды) с сохранённым прогрессом.
3. **Given** два разных игрока (две чистые установки) в один и тот же день, **When** каждый получает
   набор, **Then** наборы совпадают (выбор зависит только от даты).

---

### User Story 2 — Прогресс копится по заездам за день (Priority: P1)

После каждого заезда его итоги (собранные монеты, идеальные переключения, пройденная дистанция)
прибавляются к прогрессу заданий текущего дня. Когда прогресс достигает цели, задание становится
выполненным.

**Why this priority**: это и есть «игровая петля» заданий; без неё задания не выполнить.

**Independent Test**: подать в логику итоги нескольких заездов и проверить прогресс и момент
выполнения, не трогая кошелёк.

**Acceptance Scenarios**:

1. **Given** задание «собрать 100 монет» с прогрессом 0, **When** закончен заезд с 37 монетами,
   **Then** прогресс 37 из 100, задание не выполнено.
2. **Given** прогресс 80 из 100, **When** закончен заезд с 30 монетами, **Then** прогресс 100 из 100
   (не больше цели), задание выполнено, логика сообщает, что оно выполнено именно этим заездом.
3. **Given** заезд закончился аварией или выходом в меню через паузу, **When** итоги учитываются,
   **Then** они прибавляются к заданиям ровно один раз — так же, как монеты этого заезда к кошельку.
4. **Given** задание уже выполнено, **When** закончен ещё один заезд, **Then** его прогресс и статус
   не меняются, а остальные задания продолжают копить прогресс.
5. **Given** задание «проехать 3000 м», **When** заезды прошли 1234,6 м и 900,9 м, **Then** прогресс
   1234 + 900 = 2134 (каждый заезд учитывается целыми метрами, дробная часть отбрасывается).

---

### User Story 3 — Забрать награду в кошелёк гаража (Priority: P1)

За выполненное задание игрок забирает награду: монеты добавляются в общий кошелёк гаража, задание
помечается как «награда получена». Забрать награду можно только один раз и только за выполненное
задание.

**Why this priority**: награда — смысл заданий для игрока; монеты тратятся на улучшения гаража.

**Independent Test**: выполнить задание, забрать награду, проверить кошелёк; повторить попытку
и попытку для невыполненного задания — убедиться в отказе без изменений.

**Acceptance Scenarios**:

1. **Given** в кошельке 100 монет и выполнено задание с наградой 40, **When** игрок забирает награду,
   **Then** в кошельке 140 монет, задание отмечено «награда получена», оба изменения сохранены.
2. **Given** награда за задание уже получена, **When** игрок снова пытается её забрать, **Then** отказ
   с сообщением «Награда за задание уже получена», кошелёк и задания не меняются.
3. **Given** задание выполнено на 37 из 100, **When** игрок пытается забрать награду, **Then** отказ
   с сообщением «Задание ещё не выполнено: 37 из 100», кошелёк и задания не меняются.
4. **Given** запрошено забрать награду за задание, которого нет в сегодняшнем наборе, **When**
   выполняется операция, **Then** отказ «неизвестное задание», ничего не меняется.

---

### User Story 4 — Новый день — новые задания (Priority: P2)

С наступлением следующего календарного дня прежний набор заменяется новым, прогресс начинается с нуля.

**Why this priority**: ежедневное обновление удерживает игрока, но фича полезна и в пределах одного дня.

**Independent Test**: сохранить состояние за 19.10, запросить задания на 20.10 и проверить новый набор
с нулевым прогрессом; запросить на 18.10 (часы переведены назад) и проверить, что набор не сбросился.

**Acceptance Scenarios**:

1. **Given** сохранён набор за 19.10 с прогрессом, **When** игра запрашивает задания 20.10, **Then**
   выдаётся набор 20.10 с прогрессом 0 у всех заданий.
2. **Given** сохранён набор за 19.10, а часы устройства показывают 18.10, **When** игра запрашивает
   задания, **Then** остаётся набор 19.10 с его прогрессом (сброса и повторных наград нет).
3. **Given** игра открыта в 23:59 19.10 и заезд закончился в 00:01 20.10, **When** учитываются итоги,
   **Then** сначала происходит смена дня, итоги заезда идут в набор 20.10.
4. **Given** за 19.10 осталось выполненное, но не забранное задание, **When** наступило 20.10,
   **Then** награда обрабатывается по правилу FR-016, а набор 20.10 выдаётся с прогрессом 0.

---

### User Story 5 — Сохранение между перезапусками и повреждённые данные (Priority: P2)

Прогресс и отметки о полученных наградах переживают перезагрузку страницы. Испорченное или
недоступное хранилище не ломает игру и не трогает кошелёк гаража.

**Why this priority**: без сохранения прогресс «за день» теряется при перезапуске; без терпимого
разбора игра может упасть.

**Independent Test**: сохранить состояние, прочитать его; подать в разбор мусор и частично
испорченные данные и проверить результат.

**Acceptance Scenarios**:

1. **Given** прогресс 37 из 100 сохранён, **When** страница перезагружена в тот же день, **Then**
   прогресс 37 из 100.
2. **Given** в хранилище неразбираемое значение заданий, **When** игра читает задания, **Then**
   выдаётся набор сегодняшнего дня с прогрессом 0, кошелёк гаража не меняется, игра не падает.
3. **Given** у одного задания сохранён прогресс «-5» или «abc», остальные корректны, **When** игра
   читает задания, **Then** у этого задания прогресс 0, остальные задания сохраняют свой прогресс.
4. **Given** хранилище запрещено браузером, **When** игрок играет и забирает награды, **Then** всё
   работает до перезагрузки страницы, игра не падает.

---

### Edge Cases

- Заезд без монет, переключений и дистанции (авария сразу) — прогресс не меняется, ошибки нет.
- Один заезд выполняет сразу несколько заданий — все они отмечаются выполненными этим заездом.
- Прогресс никогда не превышает цель; «лишнее» не переносится ни на другие задания, ни на завтра.
- Монеты, полученные как награда за задание, НЕ считаются «собранными монетами» для заданий.
- Итоги заезда с недопустимыми значениями (отрицательные, дробные монеты/переключения, не число) —
  громкий отказ, задания не меняются.
- Смена дня во время открытой игры: логика проверяет дату при каждой операции, а не только при
  запуске.
- Переход часов назад не сбрасывает набор и не позволяет повторно получить награды прошлого дня.
- Сохранённый набор из будущего дня (часы переведены назад после игры) остаётся действующим, пока
  дата устройства не догонит или не обгонит его.
- Сохранённая отметка «награда получена» у задания, которое по сохранённому прогрессу не выполнено, —
  трактуется как «награда получена» (повторно не выплачивается).
- Не удалось сохранить задания после получения награды (хранилище отказало) — в текущей сессии
  награда считается полученной и повторно не выдаётся.

## Requirements *(mandatory)*

### Functional Requirements

**Задание и набор дня**

- **FR-001**: Задание MUST иметь: идентификатор (уникален в пределах дня), вид, цель (целое > 0),
  прогресс (целое от 0 до цели), признак «выполнено» (прогресс = цель), признак «награда получена»
  и размер награды в монетах (целое > 0).
- **FR-002**: Набор дня MUST содержать ровно 3 задания разных видов и быть привязан к календарному
  дню (дата по местному времени устройства игрока).
- **FR-003**: Виды заданий MUST включать как минимум: «собрать монеты» (сумма монет за заезды),
  «идеальные переключения» (сумма идеальных переключений вверх), «проехать дистанцию» (сумма метров).
  Состав пула видов: [NEEDS CLARIFICATION: только эти три вида (тогда каждый день — по одному
  заданию каждого вида, меняются только цели и награды) или пул шире (например, «очки за один
  заезд», «максимальная скорость», «прыжки») и 3 вида выбираются из него?]
- **FR-004**: Выбор набора MUST быть детерминированным по дате: одна и та же дата всегда даёт один и
  тот же набор (виды, цели, награды), независимо от числа перезапусков и от устройства. Набор дня
  MUST отличаться от набора предыдущего календарного дня хотя бы одним заданием (видом или целью).
- **FR-005**: Цель каждого задания MUST выбираться из заранее заданных уровней сложности вида
  (см. Assumptions), награда MUST определяться уровнем сложности.

**Прогресс**

- **FR-006**: Итоги заезда MUST учитываться в заданиях в тот момент, когда заезд заканчивается
  (авария или выход в меню через паузу), ровно один раз на заезд — в той же точке, где монеты заезда
  зачисляются в кошелёк гаража.
- **FR-007**: Итоги заезда MUST состоять из: числа собранных монет, числа идеальных переключений и
  пройденной дистанции в целых метрах (дробная часть отбрасывается); все три — целые ≥ 0.
- **FR-008**: Учёт итогов MUST прибавлять соответствующее значение к прогрессу каждого невыполненного
  задания и ограничивать прогресс целью; выполненные задания MUST не меняться.
- **FR-009**: Учёт итогов MUST сообщать, какие задания стали выполненными именно этим заездом
  (чтобы игра могла это показать).
- **FR-010**: Перед учётом итогов логика MUST проверить текущую дату и при наступлении нового дня
  сначала сменить набор (FR-014), а затем учитывать итоги в новом наборе.

**Награда**

- **FR-011**: Забрать награду MUST быть возможно только за задание сегодняшнего набора, которое
  выполнено и за которое награда ещё не получена.
- **FR-012**: Успешное получение награды MUST увеличить кошелёк гаража ровно на размер награды,
  отметить задание «награда получена» и вернуть новое состояние заданий и новый гараж; уровни
  улучшений гаража MUST не меняться.
- **FR-013**: Отказ в получении награды MUST сопровождаться понятным сообщением на русском и MUST
  оставлять задания и кошелёк без изменений:
  - задание не из сегодняшнего набора — «неизвестное задание: "<id>"»;
  - задание не выполнено — «Задание ещё не выполнено: <прогресс> из <цель>»;
  - награда уже получена — «Награда за задание уже получена».
  Ошибка формата входа (идентификатор не строка) — отдельная ошибка типа.

**Смена дня**

- **FR-014**: Если текущая дата позже даты сохранённого набора, логика MUST заменить набор набором
  текущей даты с нулевым прогрессом.
- **FR-015**: Если текущая дата раньше даты сохранённого набора (часы переведены назад), логика MUST
  оставить сохранённый набор без изменений.
- **FR-016**: Незабранные награды предыдущего дня при смене дня обрабатываются так:
  [NEEDS CLARIFICATION: что происходит с выполненным, но не забранным заданием при смене дня —
  награда сгорает, зачисляется в кошелёк автоматически или остаётся доступной к получению?]

**Хранение и повреждённые данные**

- **FR-017**: Состояние заданий (дата набора, задания с прогрессом и отметками о наградах) MUST
  сохраняться отдельно от гаража, под своим ключом хранилища, после каждого изменения (учёт заезда,
  получение награды, смена дня) и переживать перезагрузку страницы.
- **FR-018**: Разбор сохранения MUST быть терпимым: неразбираемое значение, неверная дата, не тот
  набор видов или число заданий — новый набор на сегодня с нулевым прогрессом; некорректный прогресс
  отдельного задания — 0, прогресс больше цели — цель; цели и награды берутся из правил набора дня,
  а не из сохранения.
- **FR-019**: Повреждение или недоступность сохранения заданий MUST не влиять на кошелёк и улучшения
  гаража и MUST не ронять игру; при недоступном хранилище задания работают до перезагрузки.
- **FR-020**: После получения награды MUST сохраняться и гараж, и задания; монеты из награды MUST
  не зачисляться повторно после перезагрузки.

**Проверка входа**

- **FR-021**: Каждая операция логики, принимающая внешний ввод (дата, итоги заезда, идентификатор
  задания), MUST сначала проверять его и при плохом вводе отказывать с понятным сообщением, не меняя
  состояние: неверный тип — ошибка типа, недопустимое значение — ошибка диапазона.
- **FR-022**: Логика заданий MUST не зависеть от экрана, хранилища и системных часов: текущая дата
  и источник случайности передаются ей извне; исходные состояния не изменяются, возвращаются новые.

**Совместимость**

- **FR-023**: Существующее поведение гаража (зачисление монет заезда, покупки, цены, разбор
  сохранения) MUST сохраниться без изменений; задания только добавляют монеты в тот же кошелёк.

### Интерфейс логики для остальной игры (поведение)

Операции, которыми игра (UI и игровой цикл) пользуется; имена и форма вызова уточняются в общем
контракте.

| Операция | Принимает | Возвращает | Отказы |
|---|---|---|---|
| Ключ дня | момент времени | календарная дата (местное время) в виде «ГГГГ-ММ-ДД» | не момент времени — ошибка типа |
| Набор дня | ключ дня | новое состояние заданий: 3 задания, прогресс 0 | неверный ключ — ошибка типа/диапазона |
| Актуализация дня | состояние заданий, ключ дня | то же состояние (тот же или более ранний день) или набор нового дня (FR-014…016) | неверный ключ |
| Разбор сохранения | сохранённое значение (может быть мусором/пусто), ключ дня | корректное состояние заданий (FR-018), никогда не падает | — |
| Итоги заезда | мир на момент конца заезда | { монеты, идеальные переключения, метры } — целые ≥ 0 | — |
| Учёт заезда | состояние заданий, итоги заезда, ключ дня | { новое состояние, список заданий, выполненных этим заездом } | итоги не того вида/отрицательные/дробные; неверный ключ |
| Получить награду | состояние заданий, гараж, id задания, ключ дня | { новое состояние, новый гараж, размер начисленной награды } | FR-013 |
| Описание для показа | состояние заданий | список из 3 заданий: id, вид, цель, прогресс, выполнено, награда получена, размер награды | — |

### Key Entities *(include if feature involves data)*

- **Вид задания**: что считается (монеты / идеальные переключения / метры), откуда берётся значение
  из итогов заезда, уровни сложности (цель + награда).
- **Задание**: id, вид, цель, прогресс, выполнено (производное: прогресс = цель), награда получена,
  размер награды.
- **Состояние заданий дня**: ключ дня («ГГГГ-ММ-ДД») + ровно 3 задания разных видов. Сохраняется
  отдельно от гаража.
- **Итоги заезда**: монеты, идеальные переключения, метры — целые ≥ 0, получаются из мира в конце
  заезда.
- **Гараж (существующий)**: кошелёк монет и уровни улучшений; задания только увеличивают кошелёк.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: В 100% проверок одна и та же дата даёт один и тот же набор из 3 заданий разных видов;
  на 365 подряд идущих датах ни один набор не совпадает с набором предыдущего дня.
- **SC-002**: Итоги каждого завершённого заезда попадают в прогресс ровно один раз — 0 случаев
  двойного учёта или потери в сквозной проверке «авария» и «выход в меню через паузу».
- **SC-003**: Каждая награда зачисляется в кошелёк не более одного раза, в том числе после
  перезагрузки страницы; все три отказа из FR-013 оставляют кошелёк и задания неизменными.
- **SC-004**: Любое повреждённое или недоступное сохранение заданий не приводит к падению игры и не
  меняет кошелёк — 100% сценариев User Story 5.
- **SC-005**: Игрок, играющий в обычном темпе, может выполнить все 3 задания дня примерно за
  5–10 заездов; одно лёгкое задание — за 1–3 заезда.
- **SC-006**: Все существующие проверки гаража и игры продолжают проходить без изменений.

## Assumptions

- **День** — календарная дата по местному времени устройства игрока; смена — в 00:00 местного
  времени. Серверного времени нет (игра офлайн).
- **Выбор набора** — детерминированный по дате (источник случайности инициализируется от даты),
  поэтому перезапуски не «перебрасывают» задания.
- **Уровни сложности и награды** (до согласования баланса; цены улучшений гаража 50/120/250):

  | Вид | Лёгкое (награда 20) | Среднее (награда 40) | Сложное (награда 60) |
  |---|---|---|---|
  | Собрать монеты | 50 | 120 | 250 |
  | Идеальные переключения | 5 | 15 | 30 |
  | Проехать дистанцию, м | 2000 | 5000 | 12000 |

  Уровень сложности каждого задания дня выбирается случайно (детерминированно по дате).
  Размер наград: [NEEDS CLARIFICATION: награда фиксирована по сложности (20/40/60) или нужен
  дополнительный бонус за выполнение всех трёх заданий дня?]
- Прогресс считается только по завершённым заездам (в конце заезда), а не непрерывно во время заезда.
- «Идеальное переключение» — то же, что уже считается в игре (переключение вверх в окне оборотов
  [0.82, 1)); дистанция — пройденный путь машины за заезд.
- В наборе дня не больше одного задания каждого вида, поэтому id задания можно делать по виду.
- Монеты из наград не идут в прогресс «собрать монеты»; задания не дают других наград, кроме монет.
- Состояние заданий хранится под собственным ключом хранилища, рядом с гаражом, по правилу
  конституции «один ключ на область».
- Один игрок на устройство, без аккаунтов и синхронизации между устройствами.
- Экраны, кнопки, уведомления о выполнении и тексты показа заданий — вне этой спеки (UI-спека).
