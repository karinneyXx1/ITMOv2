# Research: Ежедневные задания

Технический контекст без NEEDS CLARIFICATION; ниже — решения по реализации, которые не задаёт
контракт.

## 1. Детерминированный выбор набора по дате
- **Decision**: зерно `rng` — хэш строки `day` (FNV-1a 32 бита) → существующий `createRng(seed)`;
  уровни `coins` и `perfectShifts` — `Math.floor(rng() * 3)`; уровень `distance` — номер дня
  (дней от 1970-01-01) `% 3`, поэтому соседние дни всегда отличаются хотя бы целью дистанции.
- **Уточнено при реализации (T004)**: первоначальное правило «если уровни совпали со вчерашними —
  сдвинуть distance» не гарантирует отличия (вчерашний набор мог быть сдвинут сам и совпасть со
  сдвинутым сегодняшним); заменено на вращение по номеру дня, тест на 365 днях проходит.
- **Rationale**: тот же генератор, что у трассы; без `Math.random` (принцип I); одна дата — один
  набор на любом устройстве; правило «отличается» проверяемо тестом на 365 днях.
- **Alternatives**: случайный выбор при первом открытии и сохранение — отвергнут: перезапуск с
  очищенным хранилищем дал бы другой набор (нарушает спеку 002, FR-004).

## 2. Календарный день и полночь
- **Decision**: `dayKey(ts)` — `new Date(ts)` → местные год/месяц/день → `YYYY-MM-DD`;
  `nextDayStart(ts)` — `new Date(y, m, d + 1).getTime()` (корректно при переходе на летнее/зимнее
  время); сравнение дней — строковое (формат фиксированной длины).
- **Rationale**: местное время по спеке 002; `Date` с явно переданным `ts` детерминирован для
  заданного часового пояса — функции остаются чистыми относительно своих аргументов.
- **Alternatives**: UTC-день — отвергнут: у игрока в UTC+3 задания менялись бы в 03:00.

## 3. Источник «сейчас» в `main.js` и проверка смены дня
- **Decision**: `now()` в `main.js` = `Date.now() + nowOffset`; тестовый хук
  `window.__metro.setNow(ts)` задаёт смещение. Проверка дня (`refreshMissionsDay`) — при загрузке,
  возврате в меню, открытии «Заданий», в конце заезда и по `setInterval` раз в 30 с (условие
  «не реже раза в минуту»), пока открыто меню или экран «Задания».
- **Rationale**: сквозной тест смены дня без ожидания полуночи (спека 003, Assumptions); логика
  не знает о хуке.
- **Alternatives**: подмена `Date` в Playwright (`page.clock`) — возможна, но хук проще и
  одинаково работает в ручной проверке из консоли.

## 4. Предпросмотр в заезде и очередь надписей
- **Decision**: в `loop` в режиме `playing`, если `missions.day === dayKey(now())`, вызывать
  `previewCompleted(missions, runResultsFromWorld(world))`; новые id копятся в `announced` (Set на
  заезд). Надписи ставятся в очередь `toastQueue`: следующая показывается после окончания текущей
  анимации (0.9 с); несколько id в один кадр → одна надпись «Задания выполнены: N».
- **Rationale**: UI FR-013 («не затирает другую надпись»); стоимость — 3 сравнения на кадр.
- **Alternatives**: пересчёт только по событиям `coin`/`shift` — отвергнут: дистанция растёт без
  событий.

## 5. Сохранение гаража и заданий вместе
- **Decision**: после `claimMissionReward`, `applyRunToMissions` и `ensureMissionDay` с
  `autoCredited > 0` сначала `saveGarage`, затем `saveMissions`; `saveMissions` возвращает
  `true/false` (контракт, п.8). Сбой записи между ними — принятый риск спеки 002 (в сессии награда
  считается полученной).
- **Rationale**: два ключа по правилу «один ключ на область»; порядок «сначала кошелёк» не даёт
  потерять монеты.

## 6. Ошибки с кодом
- **Decision**: вспомогательная `missionError(Cls, code, message)` создаёт `TypeError`/`RangeError`
  и проставляет `err.code`.
- **Rationale**: контракт, раздел 4; `instanceof` и текст как у гаража.
