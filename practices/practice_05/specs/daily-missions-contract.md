# Общий контракт: Ежедневные задания (UI ↔ логика)

**Стороны**: `specs/001-daily-missions-ui` (Команда 1, UI) и `specs/002-daily-missions-logic`
(Команда 2, логика).
**Статус**: v1.1, принят владельцем продукта 2026-10-19 (v1.0 — первая итерация, v1.1 — решения по
вопросам команд после сверки спек с v1.0, раздел 1.1).
**Правило** (конституция, принцип VI): обе спеки обязаны соответствовать этому контракту; код,
расходящийся с контрактом, — дефект. Изменение контракта — только решением человека, с
обновлением обеих спек.

## 1. Решения согласования

| # | Расхождение | Решение |
|---|---|---|

| 4 | UI должен различать виды ошибок | У ошибок логики есть поле `code` (раздел 4) |
| 5 | UI нужна прибавка заезда по каждому заданию | Учёт заезда возвращает `gains` |

### 1.1 Итерация 2 (v1.1): вопросы команд после сверки спек с v1.0

| # | Вопрос (кто нашёл) | Решение |
|---|---|---|
| 10 | Часы переведены назад: `stale-day` при «Забрать» повторялся бы бесконечно (логика) | `stale-day` — только если день в id **раньше** `day`; id из более позднего дня (часы откатили) обрабатывается как обычно по сохранённому набору |

## 2. Данные

### 2.1 Вид задания (`type`)
`"coins"` | `"perfectShifts"` | `"distance"`. Каталог видов расширяем (новый вид — новая запись
каталога), но в этой версии набор дня всегда содержит ровно эти три вида в этом порядке.

### 2.2 Задание
```
{ id: "2026-10-19:coins", type: "coins", level: 0|1|2, target: 60, reward: 20,
  progress: 0, claimed: false }
```
- `id` — `"<day>:<type>"`, уникален в пределах дня и между днями.
- `progress` — целое, `0 ≤ progress ≤ target`.
- «выполнено» — производное: `progress === target`.

### 2.3 Состояние заданий дня
```
{ day: "2026-10-19", missions: [coins, perfectShifts, distance], seen: false }
```
`day` — календарная дата по местному времени (`YYYY-MM-DD`). `seen` — открывал ли игрок экран
«Задания» в этот день; при смене дня `false`.

### 2.4 Итоги заезда
```
{ coins: 57, perfectShifts: 2, distance: 836 }   // целые ≥ 0; distance = floor(player.z)
```

### 2.5 Уровни сложности (цели; награда 20 / 40 / 60)

| Вид | Лёгкое (20) | Среднее (40) | Сложное (60) |
|---|---|---|---|
| `coins` | 60 | 150 | 300 |
| `perfectShifts` | 3 | 8 | 12 |
| `distance`, м | 1000 | 3000 | 6000 |

Замер (автопилот, 30 трасс): заезд до аварии ≈ 57–104 монеты, 2 идеальных переключения,
840–1500 м. Лёгкое ≈ 1 заезд, среднее ≈ 2–3, сложное ≈ 5.

## 3. Операции логики (`game.js`, чистые функции)

Время и «сегодня» приходят параметром; исходные объекты не мутируются; ввод проверяется первой
строкой (принципы I, II).

| Функция | Вход | Выход | Ошибки (`code`) |
|---|---|---|---|
| `dayKey(ts)` | ms | `"YYYY-MM-DD"` (местное время) | `invalid-input` |
| `nextDayStart(ts)` | ms | ms начала следующих местных суток | `invalid-input` |
| `createDailyMissions(day)` | ключ дня | состояние дня, прогресс 0, `seen: false`; детерминировано по дате | `invalid-input` |
| `parseMissions(raw, day)` | строка/null, ключ дня | корректное состояние; **никогда не бросает** при корректном `day`; набор с днём позже `day` остаётся действующим | — |
| `ensureMissionDay(state, garage, day)` | состояние, гараж, ключ дня | `{ state, garage, autoCredited, dayChanged }` | `invalid-input` |
| `runResultsFromWorld(world)` | мир | итоги заезда (2.4) | `invalid-input` |
| `previewCompleted(state, results)` | состояние, итоги заезда **на текущий момент** | `[id]` заданий, которые эти итоги впервые довели бы до цели; состояние не меняется | `invalid-input` |
| `applyRunToMissions(state, garage, results, day)` | состояние, гараж, итоги, ключ дня | `{ state, garage, autoCredited, dayChanged, gains: { [id]: n }, completed: [id] }` | `invalid-input` |
| `claimMissionReward(state, garage, id, day)` | состояние, гараж, id, ключ дня | `{ state, garage, reward }` | `invalid-input`, `stale-day`, `unknown-mission`, `not-completed`, `already-claimed` |
| `markMissionsSeen(state)` | состояние | состояние с `seen: true` | — |
| `describeMissions(state)` | состояние | `[{ id, type, level, target, progress, completed, claimed, reward }]` | — |

Правила:
- **Актуализация дня** (`ensureMissionDay`; её же вызывает `applyRunToMissions` первой):
  `day` позже `state.day` → незабранные награды выполненных заданий зачисляются в
  `garage.coins` (`autoCredited` = сумма, 0 если нечего), новый набор с прогрессом 0,
  `dayChanged: true`. `day` равен или раньше → всё без изменений, `autoCredited: 0`,
  `dayChanged: false`. Пропущенные дни ничего не дают.
- **Учёт заезда**: к каждому невыполненному заданию прибавляется значение его вида, прогресс
  ограничен целью; `gains[id]` — реально прибавленное (0, если ничего); `completed` — задания,
  ставшие выполненными этим заездом. Монеты наград в итоги не входят.
- **Получение награды**: если день в `id` **раньше** `day` → `stale-day`; иначе задание должно быть
  в сохранённом наборе (`unknown-mission`), выполнено и не получено. Если `day` раньше
  `state.day` (часы откатили), награда за задание сохранённого набора выдаётся как обычно. Успех: `garage.coins += reward`, `claimed: true`. Уровни
  гаража не меняются. При любой ошибке состояние и гараж не меняются, автозачисления нет.

## 4. Ошибки

Ошибки логики — `TypeError` или `RangeError` с полем `code` и текстом на русском. Неверный тип
входа → `TypeError`, неверное значение (отрицательное число, дата `2026-13-45`) → `RangeError`;
у обеих `code: "invalid-input"`. Нарушения правил — `RangeError` с кодами ниже.

| `code` | Текст (`message`) | Что делает UI |
|---|---|---|
| `invalid-input` | описание неверного ввода | общий текст «Не удалось забрать награду. Попробуй ещё раз.» |
| `stale-day` | «Задания устарели — наступил новый день» | показывает текст, вызывает `ensureMissionDay`, перерисовывает; при `autoCredited > 0` — «Вчерашние награды: +N монет в гараж» |
| `unknown-mission` | «неизвестное задание: "<id>"» (для логов) | показывает общий текст «Не удалось забрать награду. Попробуй ещё раз.», перерисовывает список |
| `not-completed` | «Задание ещё не выполнено: <прогресс> из <цель>» | показывает текст |
| `already-claimed` | «Награда за задание уже получена» | показывает текст, перерисовывает строку |

Любое другое исключение из логики при загрузке или показе → UI переходит в состояние «Задания
сейчас недоступны» (UI FR-020), остальная игра работает.

## 5. Связка в `main.js` (кто, когда, что вызывает)

- Ключ хранилища **`metro-rush-missions`** (JSON состояния 2.3), отдельно от `metro-rush-garage`.
  `loadMissions(day)` — `parseMissions` в `try/catch`; `saveMissions(state)` → `true`/`false`.
  После любого изменения кошелька сохраняются и гараж, и задания.
- **Загрузка страницы и меню**: `parseMissions` → `ensureMissionDay`; то же при каждом возврате в
  меню и раз в минуту, пока меню открыто; при `autoCredited > 0` — сообщение в меню (UI FR-016),
  гараж и задания сохраняются.
- **Открытие экрана «Задания»**: `ensureMissionDay` → `markMissionsSeen` → сохранить → показать.
  Пока экран открыт — `ensureMissionDay` не реже раза в минуту (таймер и смена дня, UI FR-017/018).
- **Во время заезда**: каждый кадр, если `state.day === dayKey(now)`,
  `previewCompleted(state, runResultsFromWorld(world))`; новые id
  (ещё не объявленные в этом заезде) → всплывающая надпись (UI FR-013). Состояние не сохраняется.
- **Конец заезда** (`finishRun()`: авария и пауза → «В меню», ровно один раз):
  `applyRunToMissions(state, garage, runResultsFromWorld(world), dayKey(Date.now()))` — тем же
  гаражом, в который уже зачислены монеты заезда; результат (`gains`, `completed`, `autoCredited`,
  `dayChanged`) показывается в блоке «Задания дня» экрана итогов (UI FR-014, FR-016).
- **«Забрать»**: `claimMissionReward(state, garage, id, dayKey(Date.now()))` в `try/catch`, обработка
  ошибок — раздел 4.
- Режим экрана **`mode = "missions"`** — как `garage`: клавиши заезда и Enter игнорируются,
  Esc — назад, M/F работают.
- Хук тестов: `window.__metro.missions` (текущее состояние заданий).

## 6. Тексты UI по виду задания

| `type` | Формулировка | Единицы прогресса |
|---|---|---|
| `coins` | «Собери <цель> монет» | монеты |
| `perfectShifts` | «Сделай <цель> идеальных переключений» | переключения |
| `distance` | «Проедь <цель> м» (с разделителем тысяч) | м |

Состояние строки (UI FR-007) из данных: `progress === 0` → «Не начато»; `0 < progress < target` →
«В процессе»; `completed && !claimed` → «Выполнено — забери награду»; `claimed` → «Получено».
