# Metro Rush: проверка баланса после правки

Правка одной константы в `game.js` может незаметно сломать игру: передачи
перестанут «попадать» в окно идеального переключения, поезда станут непроходимы,
очки улетят в разы. Юнит-тесты это не ловят — они проверяют правила, а не ощущение
от игры. Этот скилл измеряет баланс числами: один и тот же набор трасс (seed 1..N)
прогоняется автопилотом **до** правки (версия из git) и **после** (текущий код).

## Когда применять
- Изменены числа геймплея в `game.js`: `GEARS`, `BASE_ACCEL`, `PERFECT_SHIFT_*`,
  `JUMP_*`, `NITRO_*`, `DIFFICULTY_DISTANCE`, параметры в `spawnPattern`, очки.
- Спрашивают: «игра стала легче/сложнее?», «как это повлияло на баланс?».
- Не нужен для правок рендера, звука, стилей — они не влияют на симуляцию.

## Процедура

1. **Сначала правила, потом баланс.** `sh scripts/check.sh` должен дать
   `CHECK: PASS`. Если тесты красные — баланс не меряем, сначала чиним.

2. **Сравнение до/после** (из папки практики):
   ```bash
   node .agents/skills/metro-balance-check/scripts/balance.js
   ```
   Параметры: `--seeds 30` (сколько трасс, 5–500), `--seconds 30` (длина заезда),
   `--ref HEAD` (с какой версией сравнивать, например `HEAD~1`).
   Скрипт сам достаёт старые `game.js` и `mcp/simulate.js` из git — ничего
   откатывать и прятать не нужно.

3. **Интерпретация.** Смотри на изменения, а не на абсолютные числа:
   | Метрика | Что значит рост | Порог «заметно» |
   |---|---|---|
   | Аварий бота, % | игра сложнее (или препятствия непроходимы) | ±10 п.п. |
   | Средняя дистанция (бот) | машина быстрее / реже бьётся | ±15% |
   | Средние очки (бот) | награда выросла (дистанция × множитель передачи, монеты, бонусы) | ±20% |
   | Доля идеальных переключений | окно идеального переключения легче поймать | ±15 п.п. |
   | Средняя макс. скорость | выше потолок передач / нитро | ±10% |
   | Без управления до аварии, с | препятствия появляются позже/реже | ±20% |

   Тревожные сигналы: аварии бота > 50% (трасса может стать непроходимой —
   проверь `step: бот ... проезжает 3 км` в `test_game.js`); доля идеальных
   переключений упала до 0 (окно `PERFECT_SHIFT_MIN` больше не достижимо).

4. **Подтверди причину на конкретном заезде** через MCP-инструмент
   `simulate_run` (сервер `metro-rush`): возьми seed, где поведение поменялось,
   прогони с `autopilot: true` и посмотри `crash` и `shifts`. Пример:
   `simulate_run({ seed: 7, seconds: 30, autopilot: true })` → на какой секунде
   и обо что разбился, какие переключения были `late`/`early`.

5. **Отчёт пользователю** — коротко:
   - таблица из шага 2;
   - 2–3 предложения: стало легче/сложнее и почему (какая константа → какая метрика);
   - один подтверждённый пример из шага 4;
   - если есть тревожный сигнал — рекомендация, но **константы сам не меняй**,
     пока не попросят.

## Ограничения
- Автопилот простой (~1 авария из 5 на 30 с даже без правок). Поэтому сравниваем
  до/после на **одних и тех же** seed, а не с «идеалом».
- Нужен коммит, где уже есть `mcp/simulate.js` (иначе скрипт честно скажет об этом).
- Измеряется логика, а не ощущения от управления в браузере — для них
  используй skill `webapp-testing`.
