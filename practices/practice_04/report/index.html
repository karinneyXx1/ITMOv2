AGENTS.md — правила проекта применялся

Агент в каждом новом чате начинает с нуля, и OpenCode автоматически даёт ему этот файл. В нём: где контракт, какой командой проверять, что нельзя трогать (git, тесты фичи A, runner), структура проекта, skills и MCP.

  • AGENTS.md — правила
  • docs/requirements.md — контракт фич A и B (требование → тест)
  • docs/style-guide.md — 5 правил кода, у каждого пример в коде и проверка

Применение: фичу B агент делал в новом чате в отдельном worktree — прочитал AGENTS.md, сам нашёл контракт, запускал sh scripts/check.sh --full и не делал коммитов.

Демо · правила«Прочитай AGENTS.md. Найди контракт и тест-пример. Назови ограничения фичи A и команду проверки проекта. Ничего не меняй.»

Агент прочитал AGENTS.md, по ссылкам из него нашёл docs/requirements.md и тест test_game.js:342, перечислил требования A1–A4 и назвал реальную команду проверки sh scripts/check.sh (и --full для A4).

Правило 2 «внешний ввод валидируется первой строкой и громко» → game.js:332–333, первая строка applyCommand() — validateCommand(command).

Подключения из настройки, которые агент ни разу не вызвал (chrome-devtools, playwright), я убрала: лишние подключения только усложняют среду. Конфиг: opencode.json.

Демо · context7«Первым действием используй MCP context7. Найди в документации Web Audio API, как проверить, что AudioContext запущен, и как ограничить время ожидания resume(). Ничего не меняй.»

Агент вызвал context7_resolve-library-id и дважды context7_query-docs по спецификации Web Audio API. Ответ по документации: запуск проверяется через context.state === "running" и событие statechange; у resume() нет встроенного таймаута, поэтому лимит делается в приложении — Promise.race с таймером. Ровно так и устроена фича B (SOUND_START_TIMEOUT_MS = 2000): документация подтвердила решение, а не «память» модели.

Hook + runner — автоматическая проверка применялся

После каждой правки агентом файла игры или MCP плагин запускает sh scripts/check.sh (синтаксис, 58 тестов логики, 12 тестов звука, 12 тестов MCP) и дописывает результат в ответ инструмента — агент сразу видит, что сломал.

  • .opencode/plugins/check-after-edit.js — hook (tool.execute.after, формат OpenCode 1.x)
  • scripts/check.sh — runner, последняя строка CHECK: PASS / CHECK: FAIL

Применение: по логам OpenCode hook сработал 19 раз (5 раз — FAIL). Во время работы над фичей B — 16 раз, из них 4 FAIL: агент получал упавший тест и исправлял его до того, как отдать работу. Отдельно показан сценарий из слайда 14: временно сломанный тест (kmh(10) → 61) дал FAIL, исправление — PASS. И ещё раз — в демо скилла (блок Б): правка BASE_ACCEL 9 → 12 → hook FAIL (упал тест MCP), откат на 9 → hook PASS.

Б. Свой skill: metro-balance-check

Устройство и автоматизация готово

Проблема. Юнит-тесты ловят сломанные правила, но не сломанный баланс: если сузить окно идеального переключения передач, все тесты зелёные, а бонус в игре перестаёт срабатывать.

Решение. Скилл сравнивает игру из последнего коммита и текущий код на одних и тех же 30 трассах (автопилот) и выводит таблицу из 6 метрик с изменениями. Старая версия берётся из git автоматически — ничего не откатывается.

.agents/skills/metro-balance-check/
├── SKILL.md            ← когда применять, 5 шагов, пороги «заметно», формат отчёта
└── scripts/balance.js  ← сравнение HEAD → текущий код
  • SKILL.md
  • scripts/balance.js

Процедура: check.sh зелёный → balance.js → интерпретация по порогам → подтверждение причины на конкретном заезде через MCP simulate_run → короткий отчёт (константы сам не меняет).

Проверка вручную: окно идеального переключения 0.82 → 0.95

В. Свой MCP: metro-rush

Полезный tool: simulate_run готово

Прогоняет заезд на настоящей логике game.js без браузера и возвращает итог. Одинаковый seed — одинаковая трасса, поэтому результат воспроизводим. Агент может проверить логику, баланс передач или проходимость трассы, не запуская игру.

Входseed (трасса), seconds (до 120), actions — команды по времени, autopilot
Выходдоехал / разбился (обо что, на какой секунде), дистанция, очки, монеты, скорость, все переключения с оценкой perfect / early / late
Ошибочный входне падает, возвращает isError с понятным текстом; неизвестную команду отклоняет та же валидация, что в фиче A
Тесты8 тестов ядра + 4 теста по настоящему протоколу MCP (клиент запускает сервер, как OpenCode)
  • mcp/server.mjs — MCP-сервер на официальном SDK
  • mcp/simulate.js — ядро симуляции и валидация входа
  • mcp/test_simulate.js, mcp/test_server.mjs — тесты
  • opencode.json — подключение "metro-rush": { "command": ["node", "mcp/server.mjs"] }
