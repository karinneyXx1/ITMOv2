# Требования (контракт) — практика 4

Две маленькие фичи Metro Rush. Для каждой: ожидаемое поведение и способ
проверки. Меняется только по поручению автора.

---

## A. Входная валидация команд игрока — ✅ реализована

Аналог из презентации: «проверить входной запрос, плохой отклонить,
при отказе не трогать дальнейшую обработку».

### Ожидаемое поведение
- **A1.** Любая команда проходит через `validateCommand()` — **первой строкой**
  `applyCommand()` в `game.js`. Допустимые команды: `left`, `right`, `jump`,
  `gearUp`, `gearDown`, `nitro`, `none`.
- **A2.** Не строка → `TypeError("command must be a string")`.
  Неизвестная строка → `RangeError('unknown command: "<команда>"')`.
- **A3.** Невалидная команда **не меняет мир**: ни игрока, ни очки, ни трассу.
- **A4.** В браузере `main.js` ловит ошибку: команда отклоняется
  (`window.__metro.command(...)` возвращает `false`), в консоль пишется
  предупреждение, игра продолжает работать.

### Как проверить
| Требование | Проверка |
|---|---|
| A1, A2 | `test_game.js`: «validateCommand: …» (3 теста) |
| A3 | `test_game.js`: «applyCommand: невалидная команда кидает исключение и не меняет мир» |
| A4 | `test_browser.py`, шаг 5 «Невалидная команда» |

Команда: `sh scripts/check.sh` (A1–A3), `sh scripts/check.sh --full` (плюс A4).

## B. Сбой зависимости: звук — ⏳ не реализована

Аналог из презентации: «ограничить ожидание LLM, вернуть понятную ошибку,
сохранить сценарии A». Наша внешняя зависимость — звук браузера
(Web Audio, `AudioContext`): его может не быть, браузер может его запретить,
а запуск (`ctx.resume()`) может зависнуть. Сейчас все такие сбои молча
проглатываются — игрок не понимает, почему тишина.

### Ожидаемое поведение
- **B1. Ограничение ожидания.** Запуск звука ждёт не дольше
  `SOUND_START_TIMEOUT_MS = 2000`. Итог запуска — один из статусов:
  | Статус | Когда |
  |---|---|
  | `available` | `AudioContext` создан и перешёл в `running` за ≤ 2 с |
  | `unsupported` | в браузере нет `AudioContext` / `webkitAudioContext` |
  | `blocked` | конструктор или `resume()` бросили ошибку / отклонили промис |
  | `timeout` | за 2 с контекст так и не перешёл в `running` |
- **B2. Понятная ошибка.** При любом статусе, кроме `available`, игрок видит
  плашку (`role="status"`, не блокирует ввод) с текстом:
  - `unsupported`: «Звук недоступен: браузер не поддерживает Web Audio. Игра продолжится без звука.»
  - `blocked`: «Звук недоступен: браузер запретил воспроизведение. Игра продолжится без звука.»
  - `timeout`: «Звук не включился за 2 секунды. Игра продолжится без звука.»

  Плашка скрывается сама через 5 с. В HUD остаётся значок «звук выключен».
- **B3. Игра не ждёт звук.** Enter запускает заезд сразу; запуск звука идёт
  параллельно и не задерживает старт и игровой цикл.
- **B4. Сбой посреди игры не роняет игру.** Если любой звуковой эффект бросит
  исключение, цикл продолжает работать, ошибка пишется в консоль один раз.
- **B5. Сценарии A сохранены.** Все проверки A проходят без изменений.

### Как проверить
| Требование | Проверка |
|---|---|
| B1 | Новый `test_audio.js` (node:test) с подменным `AudioContext`: нет конструктора → `unsupported`; конструктор бросает → `blocked`; `resume()` никогда не завершается → `timeout` не позже чем через ~2 с; нормальный → `available` |
| B2, B3 | `test_browser.py`: страница открыта с удалённым `AudioContext` (`add_init_script`) → плашка с текстом `unsupported` видна, Enter запускает заезд, команды работают |
| B4 | `test_audio.js`: эффект, который бросает, не пробрасывает исключение наружу |
| B5 | `sh scripts/check.sh --full` — все тесты A зелёные |

Разрешено в рамках B: добавить запуск `node test_audio.js` в `scripts/check.sh`
(единственная разрешённая правка runner'а). Тесты A не менять.
