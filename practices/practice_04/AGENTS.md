## Коротко: с чего начать
- **Контракт:** `docs/requirements.md` — фичи A и B, ожидаемое поведение и проверки
- **Стиль кода:** перед изменением кода прочитай `docs/style-guide.md`
- **Пример теста:** `test_game.js` → «applyCommand: невалидная команда кидает исключение и не меняет мир»
- **Проверка:** `sh scripts/check.sh` (последняя строка `CHECK: PASS`/`CHECK: FAIL`)
- **Новая фича или багфикс:** через skill `test-driven-development` — сначала падающий тест
- **Не меняй** контракт (`docs/requirements.md`) и runner (`scripts/check.sh`) без поручения. Git не трогай.

## Проект
Metro Rush (бывш. Race Mini) — браузерный раннер-гонка в духе мобильных
"бесконечных бегунов": машина мчится по трём путям метро, игрок уходит от
поездов, перепрыгивает барьеры, собирает монеты и **сам переключает передачи**.
Полноэкранный псевдо-3D на canvas, граффити-стиль. Без бэкенда, без сборки,
открывается напрямую через `index.html`.

## Стек
- Язык: JavaScript (vanilla, ES2020+), без TypeScript
- Рендер: HTML5 Canvas 2D (псевдо-3D проекция), UI — HTML/CSS поверх canvas
- Звук: Web Audio API, всё синтезируется кодом (никаких аудиофайлов)
- Тесты: встроенный `node:test` / `node:assert`; браузерные — Python Playwright
- Зависимости: в **игре** НЕТ npm-пакетов — открыл `index.html`, и работает.
  Единственное исключение — папка `mcp/` (инструмент для агента, не часть игры):
  там SDK MCP и zod. Шрифты (Bungee, Rubik) — с Google Fonts, без интернета
  работает фолбэк на системные

Поток данных за кадр: `main.js` читает ввод → `applyCommand(world, cmd)` /
`step(world, dt, input, rng)` из game.js → новый `world` + `world.events`
→ `render.js` рисует, `audio.js` звучит, `main.js` обновляет HUD.

## Игровая модель (game.js)
- `world = { player, objects, score, coins, perfectShifts, maxSpeed, time, events, ... }`
- Команды: `left`, `right`, `jump`, `gearUp`, `gearDown`, `nitro`, `none`.
  Тормоз — не команда, а зажатая клавиша: `step(..., { brake: true })`.
- КПП: 5 передач, у каждой диапазон скоростей `GEARS[i] = {min, max}`.
  `rpm()` — доля диапазона. Переключение вверх при `rpm ∈ [0.82, 1)` —
  "идеальное": буст скорости + бонус очков; на отсечке — "поздно";
  ниже 0.45 — "рано"; понижение на высокой скорости — "перекрут".
- Трасса генерируется паттернами через `rng`, переданный снаружи
  (`createRng(seed)`); у каждого паттерна есть гарантированно свободный
  от поездов путь `safeLane` — трасса всегда проходима (это проверяет тест-бот).
- `world.events` — события ТОЛЬКО последнего вызова (`coin`, `shift`, `jump`,
  `crash`, ...). Их потребляют рендер/звук/HUD; game.js о них ничего не знает.

## Конвенции по коду и тестам
- Разделяй логику и рендер: правила — чистые функции без `document`/`window`/
  `canvas`/`Math.random`; рендер, звук, DOM и ввод — отдельно.
- Чистая функция: одинаковый вход → одинаковый выход, исходное состояние не
  мутируется (`{ ...state }`). Случайность — только через параметр `rng`.
- Входная валидация — отдельная функция `validateX`, вызывается ПЕРВОЙ строкой
  в операции, принимающей внешний ввод. Бросает `TypeError`/`RangeError` с
  понятным сообщением, не возвращает `null`/`false` молча.
  Пример: `validateCommand()` — первая строка `applyCommand()`.
- `main.js` оборачивает команды в try/catch: невалидная команда логируется и
  отклоняется, игра не падает.
- Клавиши читаются по `e.code`, а не `e.key` — управление работает при любой
  раскладке (в т.ч. русской).
- Новая механика = новые константы в начале game.js + функции + тесты на
  happy path, границы и невалидный ввод. Только потом — рендер и HUD.
- Тесты: только `node:test`/`node:assert`. Один тест = одна проверка поведения,
  говорящее название на русском.
- Не добавлять npm-зависимости, TypeScript, бандлеры в игру без явного
  согласования — она должна оставаться "открыл файл — заработало". Код игры
  не импортирует ничего из `mcp/`.
- Git не трогать: папка — часть большого репозитория курса, коммитит автор сам.

## Скиллы (`.agents/skills`, список — в skills-lock.json)
- **webapp-testing** — любая задача "проверь, что игра работает" / "посмотри,
  что в браузере". Воркфлоу: скриншот → осмотр DOM → действия (клавиши) →
  повторный скриншот. Для доступа к состоянию игры используй
  `window.__metro.world`, `window.__metro.mode`, `window.__metro.command(cmd)`.
- **frontend-design** — любые изменения внешнего вида (HUD, меню, карточки,
  стиль сцены). Сначала сверяйся с docs/DESIGN.md, потом с этим скиллом.
- **test-driven-development** — любая новая фича или багфикс в логике.
  Цикл: тест → увидеть правильное падение (`sh scripts/check.sh`) → минимальный
  код → зелёный. Перед написанием тестов прочитай его `writing-good-tests.md`.
- **metro-balance-check** (свой) — после правки чисел геймплея в `game.js`
  (передачи, ускорение, прыжок, нитро, сложность, очки): сравнивает баланс
  «до/после» на одних и тех же трассах и объясняет, стало легче или сложнее.

Установка/восстановление скиллов: `npx skills experimental_install`.

## MCP (opencode.json)
- **context7** — актуальная документация по Canvas 2D, Web Audio, Playwright,
  когда нужен точный API.
- **metro-rush** (свой, `mcp/server.mjs`) — инструмент `simulate_run(seed, seconds,
  actions, autopilot)`: прогоняет заезд на логике `game.js` без браузера и
  возвращает итог (краш, дистанция, очки, переключения). Используй, чтобы проверить
  баланс КПП или проходимость трассы. Папка `mcp/` — единственное место с
  npm-зависимостями (SDK MCP, zod), сама игра их не использует.
  Установка: `cd mcp && npm install`, тесты: `cd mcp && npm test`.

## Дизайн
Полный визуальный бриф — в docs/DESIGN.md. Коротко: граффити-стиль уличного
раннера — жёлто-оранжевые градиентные надписи с толстой тёмно-синей обводкой,
облака стально-голубых пузырей с бликами, белые искры-звёздочки, белые карточки
с жёсткой смещённой тенью, кнопки-пилюли. Чужие логотипы, названия и персонажей
не копируем — только язык стиля.

## Как проверить работу
Единая команда проверки — **`sh scripts/check.sh`** (~2 с): синтаксис JS,
`test_game.js`, `test_audio.js`, тесты MCP (`cd mcp && npm test`; если нет
`mcp/node_modules` — шаг пропускается с подсказкой). Последняя строка —
`CHECK: PASS` или `CHECK: FAIL`.
- `sh scripts/check.sh --full` — плюс браузерный тест `test_browser.py`
  (окружение: `python3 -m venv venv && venv/bin/pip install playwright && venv/bin/playwright install chromium`)
- Вручную: открыть `index.html` в браузере, Enter — поехали.

Не меняй `scripts/check.sh` и не ослабляй тесты ради зелёного результата без
явного поручения.

## Hook: автопроверка после правки
`.opencode/plugins/check-after-edit.js` — после каждого `edit`/`write`/`apply_patch`
файла игры или MCP (`game.js`, `render.js`, `audio.js`, `main.js`, `test_game.js`,
`test_audio.js`, `index.html`, `styles.css`, `mcp/simulate.js`, `mcp/server.mjs`,
`mcp/test_*`) запускает `sh scripts/check.sh` и дописывает результат в ответ
инструмента. Вывод хука не виден в интерфейсе OpenCode — он приходит тебе в
ответе инструмента. Увидел `[hook check-after-edit] ... FAIL` — сначала исправь
ошибку, потом продолжай задачу.
