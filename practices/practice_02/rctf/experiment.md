# R.C.T.F.

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- **Role:** инженер по нагрузочному тестированию, отвечающий за воспроизводимость прогонов
- **Context:** сервис FastAPI (`POST /api/reviews`), правила REL-1 (таймаут 10с), API-1 (лимит 20000 символов, отказ 413), OBS-1 (лог только request_id/длительность/статус); инструмент — k6; реализация внешнего LLM неизвестна, используется mock
- **Task:** добавить в файл раздел с форматом фиксации результатов нагрузочного прогона — куда и в каком виде сохранять метрики каждого сценария
- **Format:** новый раздел "## Формат отчёта" с таблицей полей отчёта (поле, тип, пример значения) и указанием, в каком файле/формате (CSV/JSON) сохраняются результаты k6


## Полный запрос

См. [`prompt.md`](prompt.md)

## Что получили

Модель добавила новый раздел "## Формат отчёта" в конец файла, не 
изменив существующие разделы. Раздел задаёт JSON как формат хранения 
результатов каждого прогона (путь `load/results/<scenario_id>_<run_id>.json`, 
формируется через `handleSummary()` k6), таблицу из 16 полей (poле | тип | 
пример значения: `scenario_id`, `run_id`, `git_commit`, метрики латентности 
p50/p95/max, `status_counts`, `mock_llm_calls`, `log_leak_marker_found`, 
`thresholds_passed` и др.), а также пояснения, как поля связаны с уже 
существующими сценариями (например, `mock_llm_calls = 0` для сценария 3, 
`log_records_total = requests_total` для сценария 5). Полный результат — 
в изменённом [`tests_load_input.md`](tests_load_input.md).
