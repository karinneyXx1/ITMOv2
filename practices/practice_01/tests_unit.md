# Unit-проверки

Изолированно тестируются `ReviewService` (`app/review_service.py`) и функции валидации/редактирования из решения в [`adr.md`](adr.md). Внешний LLM везде заменяется mock-реализацией протокола `LLM` (`review_service.py:4-6`: `def generate(self, prompt: str) -> str`), которая записывает переданный `prompt` и возвращает заранее заданный текст или бросает исключение. Номера строк — по итоговым файлам после применения `TRAINING_PR.diff`.

## Как использовали AI

- Для чего: составление изолированных проверок для каждого этапа решения из `adr.md` (редактирование секретов, лимит длины, таймаут/исключения LLM, парсер и фильтр OUT-1/QA-1, запись лога OBS-1) с привязкой к строкам `TRAINING_PR.diff` и рискам P1-02.
- Тип промпта: master prompt (build).
- Строка в [`prompts.md`](prompts.md): P1-03.
- Что проверили и исправили сами: сверила таблицу целостности diff (review_service.py new 23≠16, api.py old 8≠10, new 17≠15) с собственным ручным пересчётом хантков из P1-02 — цифры совпадают. Проверила, что каждая строка теста ссылается на конкретное правило и реальную строку кода, а не общую формулировку.
